# APS GDT Reload (CS/SS Segment-Selector Reload)

## Scope delivered

Closed the "Segment-selector reload" gate `aps-owned-gdt.md` and `aps-exception-entry-stub.md`
both left open: replacing the firmware's GDT with an APS-owned one, and actually activating it,
not just loading it.

`CPU.LoadGDT` alone leaves `CS` holding its old selector value, which after that call indexes a
possibly-unrelated descriptor in the *new* table -- there is no `MOV CS, imm` in x86-64; the only
way to change `CS` is a far jump or far return. Added `CPU.ReloadCodeSegment(codeSelector)`,
lowering to the standard "push target CS; push target RIP; far-return" trick: push the selector,
compute the address of the very next instruction via a RIP-relative `LEA` (a same-function forward
reference, patched immediately -- no cross-symbol relocation needed), push that, then `RETFQ`. The
whole sequence reads as an ordinary statement that "returns" right after itself.

That alone was not enough to keep interrupt delivery working, and finding out why is the real
content of this report. `SS` still holds whatever selector the firmware assigned, which may not
even be a valid index into the new (typically much smaller) GDT. That is not a fault by itself --
but `IRETQ` re-validates and reloads `SS` from every interrupt frame it pops, and a stale selector
does fault there (`#GP`), which (correctly, per the exception-entry table's own design) is treated
as an unrecognized vector and parks the processor rather than resuming -- a clean hang, not a
crash, and easy to misread as "the far jump doesn't work" when the far jump is actually fine. Added
`CPU.ReloadStackSegment(selector)`, lowering to `MOV SS, AX` (`8E D0`), reloading `SS` to the new
GDT's own data descriptor. This is not hygiene the way reloading `DS`/`ES`/`FS`/`GS` would be
(those aren't touched by interrupt frame push/pop) -- it is required for any interrupt to be
deliverable at all after a GDT switch.

New encoder primitives (`arco/x86_64_encoder.hpp`): `retfq`, `mov_ss_rax`.

## Validation

- exact encoder unit tests for both new primitives, byte-for-byte against the x86-64 architecture
  encoding;
- A-MIR/x86-64 reveal smoke (`systems_arco_basic_gdt_reload_smoke.sh`): confirms
  `CPU.ReloadCodeSegment`/`CPU.ReloadStackSegment` lower to `MEMORY.RELOADCS`/`MEMORY.RELOADSS`,
  and that the generated bytes match the exact expected instruction sequence (push/lea/push/retfq,
  then `8E D0`);
- **the real proof, executed under QEMU/OVMF, not just checked at compile time**: a dedicated
  fixture (`aps-gdt-reload.abas`) builds a genuinely new, independent GDT and TSS within the
  APS-owned identity-mapped region (not reusing the firmware's own selector value the way
  `aps-breakpoint-recovery.abas` deliberately does), activates them via `LoadGDT` +
  `ReloadCodeSegment` + `LoadTaskRegister` + `LoadIDT` + `ReloadStackSegment`, reads `CS` back
  *live* to confirm it names the new table's own code selector (8) rather than whatever the
  firmware had, and then recovers a deliberate `CPU.Breakpoint` using IDT gates built against that
  new selector -- a combined proof that the new GDT is genuinely what the CPU is executing under,
  not merely loaded and ignored. Verified deterministic across repeated runs;
- `stdlib/descriptor_table_policy.abas`'s `ActivateDescriptorTables` now actually performs the CS
  reload it was always meant to (added a `codeSelector` parameter); its existing AST/A-MIR-level
  smoke fixture (`descriptor-table-policy.abas`) updated to match the new call shape;
- full existing test suite (43/43) passes.

## Remaining activation gate

`DS`/`ES`/`FS`/`GS` are left holding their old (firmware) selector values. Untouched by interrupt
delivery, so nothing in this proof required reloading them, but leaving stale selectors in place
is not something to build further on without revisiting -- any future code that uses an explicit
segment-override prefix, or firmware code invoked after this point (there shouldn't be any, since
boot services are already exited by here) could still be affected. A follow-up hygiene pass
reloading all four to the new GDT's data descriptor (cheap: the same `MOV Sreg, AX` pattern
`mov_ss_rax` already demonstrates, once per remaining register) is worth doing before this track
relies on segment state being fully clean.

TSS still carries a zeroed `RSP0`/`IST1` (`aps-tss-emergency-stacks.md`'s real emergency-stack
reservation through PRD/VRD is separate future work) -- safe here only because no ring transition
or IST-routed vector (`#DF`) is ever exercised by this proof. That is the next real dependency this
unblocks: with CS/SS reload now working, building a validated emergency stack and testing `#DF`
recovery through IST1 becomes possible for the first time.
